# ShareIt

Сервис для шеринга вещей: пользователи публикуют вещи, которыми готовы поделиться,
и берут в аренду вещи других пользователей. Если нужной вещи нет в сервисе, можно
оставить запрос (`ItemRequest`), а бронирование (`Booking`) закрывает вещь от
других пользователей на время аренды.

Текущий спринт — каркас приложения и веб-слой для вещей (`Item`) и пользователей
(`User`): контроллеры, DTO, мапперы, сервисы и in-memory хранилище. Работа
с базой данных, бронирования и запросы вещей будут реализованы в следующих спринтах.

## Стек

- Java 21, Spring Boot 3.3.2 (Spring MVC)
- Lombok
- Bean Validation (`spring-boot-starter-validation`)
- Maven

## Запуск

> На хосте с несколькими установленными JDK убедитесь, что сборка идёт под
> **JDK 21** (`java.version` в `pom.xml`). При компиляции под JDK 23 с
> `--release 21` Lombok в этой связке не генерирует геттеры/сеттеры — это
> известное ограничение самого Lombok, не связанное с кодом проекта.

```bash
export JAVA_HOME=$(/usr/libexec/java_home -v 21)
mvn spring-boot:run
```

Приложение поднимется на `http://localhost:8080`.

## API

### Users

| Метод | Путь | Описание |
|---|---|---|
| `POST` | `/users` | Создать пользователя |
| `GET` | `/users` | Список всех пользователей |
| `GET` | `/users/{userId}` | Получить пользователя по id |
| `PATCH` | `/users/{userId}` | Частично обновить пользователя (имя и/или email) |
| `DELETE` | `/users/{userId}` | Удалить пользователя |

### Items

Во всех запросах, кроме поиска и просмотра конкретной вещи, требуется заголовок
`X-Sharer-User-Id` — id пользователя, от лица которого выполняется запрос.

| Метод | Путь | Описание |
|---|---|---|
| `POST` | `/items` | Добавить вещь. Пользователь из `X-Sharer-User-Id` становится владельцем |
| `PATCH` | `/items/{itemId}` | Изменить название/описание/доступность. Только владелец |
| `GET` | `/items/{itemId}` | Просмотреть вещь по id (доступно любому пользователю) |
| `GET` | `/items` | Список вещей текущего владельца |
| `GET` | `/items/search?text={text}` | Поиск доступных для аренды вещей по названию/описанию |

## Обработка ошибок

- `400 Bad Request` — не прошла валидация входных данных
- `403 Forbidden` — попытка редактировать вещь не её владельцем
- `404 Not Found` — пользователь или вещь не найдены
- `409 Conflict` — email уже занят другим пользователем

Ответ об ошибке: `{"error": "текст сообщения"}`.
